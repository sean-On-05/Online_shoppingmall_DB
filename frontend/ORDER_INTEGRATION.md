# 주문 API 연동

이 프론트엔드는 `백엔드 API 연동 명세서.docx`와 `origin/feature/order-inventory`의 API를 기준으로 구현했습니다. 현재 `main`의 이전 백엔드에는 결제·배송 API가 없으므로 해당 백엔드 변경과 함께 사용해야 합니다. 기존 DB에 새 스키마가 적용되어 있는지도 확인하세요.

- 주문서의 배송 정보 6개 문자열을 `POST /api/orders`로 전송합니다. 선택 항목은 빈 문자열입니다.
- 응답의 `orderId`로 주문 상세에 이동하며, 여기서 결제 수단과 모의 성공·실패를 선택합니다.
- 결제 실패 시 동일 주문의 `/payment` API로 재시도합니다. 주문은 다시 생성하지 않습니다.
- 관리자는 결제 완료·주문접수·배송 미등록 주문에만 배송을 등록합니다. `POST /shipment`에는 `{}`를 전송합니다.
- 배송준비 → 배송중 → 배송완료는 `/shipment`의 PATCH로 처리합니다.
- 주문접수·배송 미등록 주문에만 관리자 취소 버튼을 표시합니다. 취소는 주문 API의 PATCH로 처리합니다.
- 재고와 주문 정보는 각 변경 API가 반환한 최신 쇼핑몰 데이터로 갱신합니다.
- 주문, 결제, 배송 상태를 독립적으로 표시합니다. 취소 후 배송지가 제거되면 빈 배송 정보 안내를 표시합니다.

## 검증

`frontend`에서 의존성을 설치한 뒤 실행합니다.

```sh
npm test
npm run build
npm run lint
```

테스트는 Node.js 22.13 이상에서 실행합니다. 상태 전이, 결제 재시도 허용 조건, 요청 경로·메서드·본문, 세션 쿠키 및 서버 오류 메시지를 검증합니다.

개발 중 별도의 브라우저 검사에서는 모의 API 응답으로 주문 생성, 결제 실패·재시도, 관리자 배송 단계, 취소 후 배송 정보 표시를 확인했습니다. 실제 Flask 서버와 DB를 연결한 통합 테스트를 대체하지 않습니다.

실제 연동 확인 순서:

1. `feature/order-inventory`의 백엔드를 새 스키마가 적용된 테스트 DB로 실행합니다.
2. 고객이 장바구니 상품을 주문하고 배송 정보를 저장했는지, 재고가 감소했는지 확인합니다.
3. 주문 상세에서 결제 실패 후 성공으로 재시도하고 새 주문이 생성되지 않는지 확인합니다.
4. 관리자 로그인 후 저장된 배송 정보를 확인하고 배송 등록 → 배송중 → 배송완료로 처리합니다.
5. 별도의 미배송 주문을 취소하고 재고 복구, 배송 정보 삭제, 완료된 모의 결제의 취소를 확인합니다.
